# SCR-301 메인화면 — Skeleton Prompt

## Context

- 화면 크기: Mobile app `393 x 852`.
- 진입: 앱 실행 또는 홈 복귀.
- 이탈: 목적지 검색 선택 시 `SCR-302`, 즐겨찾기 선택 시 목적지 확인 흐름, 스케줄 시작 시 목적지 확인을 건너뛰고 `SCR-305` 주행 옵션으로 바로 진입한다.
- 화면 유형: FLOW-003의 시작 화면. 목적지 검색, 즐겨찾기, 스케줄 기반 시작, 최근 출동 내역을 한 화면에서 확인한다.

## Flow Coverage

- 기본 자율주행 생성 플로우 시작: `SCR-301 -> SCR-302 -> SCR-303 -> SCR-304 -> SCR-305 -> SCR-307 -> SCR-309 -> SCR-311`.
- 수동주행 생성 플로우 시작: `SCR-301 -> SCR-302/303 -> SCR-304 -> SCR-305 -> SCR-308 -> SCR-310 -> 완료`.
- 스케줄 시작 전용 화면 상태는 만들지 않는다. 스케줄 시작은 목적지 확인을 거치지 않고 SCR-305 주행 옵션 설정으로 바로 이동하는 흐름으로 표시한다.
- 이 화면의 skeleton 옆에는 작은 flow rail을 두어 `홈 -> 주소 선택 -> 목적지 확인`과 `홈 -> 스케줄 시작 -> 주행 옵션`이 다른 진입 경로임을 확인하게 한다.

## Skeleton Objective

홈에서 목적지 기반 주행 생성으로 들어가는 경로가 빠짐없이 보이는지 검증한다. 검색 진입, 즐겨찾기 선택, 스케줄 시작이 서로 다른 진입 경로라는 점과 최근 출동 내역이 주행 생성 CTA와 혼동되지 않는지가 핵심이다.

## Structural Layout

- 최상위 섹션: `SCR-301.main-skeleton-set`.
- 섹션 안에 `default`, `no-schedule` 상태 프레임을 둔다.
- `@header`: 기관명, 메뉴 또는 계정 진입 위치.
- `@content`: 목적지 검색 카드, 즐겨찾기 바로가기 2개, 스케줄 카드, 최근 출동 내역 카드 순서.
- `@flow-rail`: 화면 오른쪽 또는 아래에 별도 낮은 위계로 배치한다. 실제 앱 UI처럼 보이지 않게 skeleton 검증용 레일로 구성한다.
- 고정 footer는 만들지 않는다.

## Controls And Feedback

- 목적지 검색 진입: `출동 주소를 검색하세요` 검색 필드 형태. 선택 시 주소 검색으로 이동하는 주 흐름이다.
- 즐겨찾기: 2개 shortcut. 즐겨찾기 편집 아이콘 위치만 표시하고 편집 플로우는 이번 skeleton 범위에 포함하지 않는다.
- 스케줄 카드: 업무명, 날짜/시간, 목적지 요약. 스케줄만을 위한 별도 준비 상태 프레임은 만들지 않는다.
- 최근 출동 내역: 최신 출동 1~2개 summary. CTA처럼 보이지 않게 정보 카드로 구분한다.
- 원격운행/원격재배치 진입 플래그는 홈 화면 상태로 만들지 않는다.

## State Variants

- `default`: 목적지 검색, 즐겨찾기, 스케줄, 최근 출동 내역이 모두 있는 상태.
- `no-schedule`: 스케줄 카드가 없고 목적지 검색이 주요 진입점인 상태.

## Floating Layers

- 이 화면에는 기본 팝업/알림이 없다.
- 즐겨찾기 편집이나 전체 스케줄은 이번 skeleton에서 별도 팝업으로 만들지 않는다.

## Skeleton UX Checks

- 홈에서 주행 생성으로 들어가는 첫 행동이 목적지 검색/즐겨찾기/스케줄 시작 중 무엇인지 구분된다.
- 최근 출동 내역이 신규 주행 생성 CTA로 오해되지 않는다.
- 홈의 진입 경로가 주소 검색/즐겨찾기/스케줄 요약으로 혼동 없이 읽힌다.
- 상태 프레임들이 하나의 `SCR-301.main-skeleton-set` 안에 묶여 같은 화면의 변형임을 알 수 있다.
- 사용자 UI에는 화면 ID, 내부 변수명, TBD, 구현 설명을 표시하지 않는다.
