# SCR-303 주소검색 결과 — Skeleton Prompt

## Context

- 화면 크기: Mobile app `393 x 852`.
- 진입: `SCR-302`에서 검색어 입력.
- 이탈: 주소 후보 또는 즐겨찾기 선택 시 `SCR-304`.
- 화면 유형: 검색어가 입력된 결과 목록 화면. 즐겨찾기는 검색 결과 상태에서도 유지된다.

## Flow Coverage

- 직접 검색 흐름: `SCR-301 -> SCR-302 -> SCR-303 -> SCR-304`.
- 검색 결과에서 즐겨찾기를 선택해도 목적지 확인으로 이동한다.
- skeleton에는 검색어 입력 후 결과 선택이 목적지 확인으로 이어지는 흐름을 flow rail에 표시한다.

## Skeleton Objective

입력된 검색어, 검색창 바로 아래 즐겨찾기 shortcut, 주소 후보 목록이 한 화면에서 충돌 없이 읽히는지 검증한다. 유사 주소가 여러 개일 때 후보 행의 구분과 선택 가능성이 명확해야 한다. 주소 후보 선택 후 최근 검색은 최대 5개, 최신순, 1개월 보관 정책으로 저장되지만 사용자 UI에는 정책 설명을 노출하지 않는다.

## Structural Layout

- 최상위 섹션: `SCR-303.address-search-results-skeleton-set`.
- 섹션 안에 `results`, `no-results` 프레임을 둔다.
- `@header`: 뒤로가기, 입력된 검색어가 있는 검색 필드, 검색 실행 아이콘.
- `@content`: 검색창 바로 아래 즐겨찾기 영역, 주소 후보 list.
- `@flow-rail`: 주소검색 결과 선택 후 목적지 확인으로 이동하는 흐름.
- 고정 footer 없음.

## Controls And Feedback

- 검색어 입력값: 예시 검색어가 들어간 상태.
- 주소 후보: 4개 list row. 도로명/상세 주소가 두 줄까지 들어갈 수 있게 한다.
- 즐겨찾기: 검색 결과 상태에서도 검색창 바로 아래에 유지한다. 편집은 별도 즐겨찾기 관리 화면으로 이어지는 흐름만 표시한다.
- 결과 없음 상태는 화면 전체를 비우지 말고 검색어와 재검색 가능한 입력을 유지한다.
- `no-results`의 `검색결과가 없습니다. 검색어를 다시 입력하세요` 안내는 결과 목록의 1번 위치에 표시한다.

## State Variants

- `results`: 주소 후보가 있는 상태.
- `no-results`: 검색 결과 없음, 재검색 가능.
- 원격운행 주소 지정은 센터 시스템에서 완료된 뒤 자율주행 진행 화면으로 이동하므로 검색 결과 화면에 별도 원격운행 상태를 만들지 않는다.

## Floating Layers

- 기본 팝업/알림 없음.
- 검색 실패를 alert처럼 띄우지 않는다. 결과 없음은 본문 상태로 처리한다.

## Skeleton UX Checks

- 검색어 수정과 후보 선택이 모두 가능한 화면으로 보인다.
- 주소 후보 행이 서로 구분되고 선택 가능성이 명확하다.
- 결과 없음도 같은 화면의 상태로 묶여 있다.
- 결과 없음 안내가 결과 목록 1번 위치에 있어 재검색 흐름과 연결된다.
- flow rail에서 다음 단계가 목적지 확인임을 확인할 수 있다.
- 사용자 UI에는 화면 ID, 내부 변수명, TBD, 구현 설명을 표시하지 않는다.
